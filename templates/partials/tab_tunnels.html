روش ۱: پورت رله (Port Relay / DNAT) سریع‌ترین سرعت

با استفاده از جدول nat و زنجیره PREROUTING فایروال هسته لینوکس، پکت‌های ورودی به یک پورت خاص مستقیماً به آی‌پی و پورت مقصد در سرور خارج یا داخل تونل ریدایرکت می‌شوند.

iptables -t nat -A PREROUTING -p tcp --dport 443 -j DNAT --to-destination 10.200.30.2:443
iptables -t nat -A POSTROUTING -j MASQUERADE
روش ۲: مالتی‌پلکس معکوس (Backhaul / Rathole / FRP) عدم نیاز به پورت باز

در این روش کلاینت از سرور ایران به سرور خارج متصل می‌شود یا برعکس؛ چندین اتصال کاربر داخل یک جریان امن فشرده ادغام (Mux) شده و حتی در پشت NAT دیتاسنتر یا فایروال بدون باز کردن پورت عمل می‌کند.

Client (Iran) ➔ TCP Mux (Backhaul/Rathole) ➔ Server (Kharej)
Zero packet leak & Full connection pooling
روش ۳: پالیسی روتینگ (Policy Routing / ip rule) هدایت کل ساب‌نت

با ایجاد جدول مسیریابی اختصاصی و ست کردن مارک در iptables یا بر اساس آی‌پی مبدا، ترافیک بدون دستکاری روت پیش‌فرض لینوکس، از طریق گیت‌وی تانل (WireGuard, GRE, VXLAN) هدایت می‌شود.

ip route add default via 10.200.30.2 table 100
ip rule add fwmark 0x1 table 100
روش ۴: تونل DNS (DNSTT / SlowDNS) شرایط اینترنت ملی

در مواقعی که تمام پورت‌های TCP و UDP خارجی فیلتر یا اینترنت قطع است، پکت‌ها داخل کوئری‌های DNS استاندارد یا DoH رمزنگاری شده و از طریق کش سرورهای DNS عبور می‌کنند.

Client ➔ DNS Query (DoH / UDP 53) ➔ Cloudflare ➔ DNSTT Server

بهینه‌سازی حیاتی MTU و پیشگیری از افت سرعت (MSS Clamping)

هر تونل مقداری هدر اضافی (Header Overhead) به هر پکت اضافه می‌کند. اگر اندازه پکت از MTU مجاز شبکه بیشتر شود، بسته تکه‌تکه (Fragment) شده یا توسط فایروال‌های DPI اپراتور دراپ می‌شود که علت اصلی کندی اینترنت و لود نشدن ویدیوهاست. پنل به صورت خودکار با قابلیت MSS Clamping سایز ماکسیمم سگمنت TCP را با پکت هماهنگ می‌کند.

پروتکل تونل هدر اضافی (Overhead) MTU پیشنهادی بهینه MSS معادل وضعیت در شبکه ایران
WireGuard 60 تا 80 بایت 1420 1380 عالی با UDP باز
GRE / IPIP 20 تا 24 بایت 1476 1436 حداکثر راندمان لینوکس
VXLAN / GENEVE 50 بایت 1450 1410 سازگاری فوق‌العاده میکروتیک
WSTunnel / GOST (WSS) متغیر (TLS Framing) 1360 - 1400 1320 ضد فیلترینگ قطعی (CDN)

توصیه‌های کلیدی برای مدیران سرور:

  • تست پایداری مداوم: همواره از ساب‌تب «ابزار تست و عیب‌یابی پایداری» برای بررسی لیتنسی و جیتر تانل‌ها استفاده کنید.
  • ترکیب رله با تانل امن: به جای پورت رله مستقیم روی آی‌پی پابلیک خارج، رله را روی آی‌پی داخلی تونل (مثل 10.200.30.2) تعریف کنید تا تمام ترافیک کاربران رمزنگاری شده و آی‌پی خارج در ایران لو نرود.
  • چرخش دامنه‌ها (Domain Rotation): برای پروتکل‌های مبتنی بر وب‌سوکت یا Reality، چند دامنه مجاز تعریف کنید تا در صورت اختلال، ترافیک به دامنه رزرو منتقل شود.
دانشنامه تخصصی انتخاب تونل (MikroTik vs Linux Anti-Censorship Tunnels) راهنمای فنی برای انتخاب مناسب‌ترین راهکار بین سرور ایران و خارج بر اساس سناریوی فیلترینگ
کلیک برای مشاهده
تونل‌های استاندارد میکروتیک (GRE, EoIP, IPIP, WG):
مستقیماً در روتربوردهای میکروتیک قابل استفاده هستند. برای شبکه‌های پایدار و دیتاسنترهایی که پروتکل‌های خام IP مسدود نیستند، بالاترین سرعت ترانزیت و کمترین لود پردازشی را دارند.
تونل‌های وب‌سوکت و TLS (GOST, WSTunnel, RTT):
ترافیک را به وب‌سوکت رمزنگاری‌شده (WSS) یا TLS استاندارد شبیه وب‌سایت‌های عادی تغییر می‌دهند. می‌توان آن‌ها را از CDN کلودفلر یا با SNI دامنه‌های مجاز عبور داد تا سیستم DPI قادر به شناسایی نباشد.
مبدل پکت‌های UDP به Fake TCP (UDP2Raw, Phantun):
در شبکه‌هایی که اپراتورها پکت‌های UDP و پروتکل‌های WireGuard، AmneziaWG و TUIC را دچار پکت‌لاس شدید می‌کنند، پکت‌ها را داخل هندشیک جعلی TCP قرار داده و مانع از مسدودسازی می‌شوند.
ترکیب روتربورد با تونل لینوکس:
می‌توانید سرور خارج را با یکی از ابزارهای ضد فیلتر (مثل GOST یا RTT) به سرور ایران متصل کنید، و سپس از سرور ایران به روتربورد میکروتیک با GRE یا L2TP ترافیک را تحویل دهید تا کاربران به اینترنت آزاد برسند.
